# W3 · `check()` API + ingestion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A FastAPI service `apifacts.api.app:app` serving `POST /v0/check` (request = contribution,
default-deny ingestion into sqlite), `GET /v0/facts/{service}`, `GET /v0/facts/{service}/{slug}`,
`GET /v0/services`, `GET /healthz`, with the OpenAPI document committed at `docs/specs/openapi-v0.json`.

**Architecture:** At startup a `FactsIndex` is built from `services/*.yaml` and `facts/**/*.yaml` under
`AGENTFACTS_REPO` (files that fail `apifacts validate` are skipped and logged). A request goes through
five pure steps — parse target (`match`), resolve service + template (`match`, reusing
`apifacts.schema.registry.match_template`), extract + normalize the signal (`normalize`), look up
facts in three tiers (`facts_index`), decide whether to store (`app` + `store`) — and the answer is
always the same six-key object. Storage is one sqlite file (`observations`, `salts`, `counters`);
rate limits are in memory (sliding window). No LLM, no network.

**Tech Stack:** Python 3.12, FastAPI 0.150 / Starlette 1.x, pydantic 2.14, sqlite3 (stdlib), pytest +
`fastapi.testclient.TestClient` (no sockets).

**Specs:** `docs/specs/03-check-contract.md` (contract), `01-fact-schema.md` (observation, service),
`05-ingestion-quorum-bot.md` § Abuse controls (drop rules), `09-work-breakdown.md` § W3 + Process.

## Decisions where spec 03 is silent (code-level; listed in the PR)

- `unknown` is **always** an object `{reason, stored_as_observation}`; `reason` is `null` when facts answer
  the signal. With an error given and tiers 1–2 empty, `reason = no_fact_for_signal` even if tier 3
  (service `rate_limit`/`availability`) facts are returned — this is how the spec's own example reads.
- Error envelope `{"error": {"code", "message", "field"}}`; 400 `unknown_field` / `invalid_request`,
  413 `body_too_large`, 429 `rate_limited` + `Retry-After`, 404 `unknown_service` / `unknown_fact`.
- `target.method` is required when `target.url` is an http(s) URL with a path (an observation needs a
  method; we never guess one into stored data). Bare host and locators need none.
- Host match is exact (no subdomains), several services may share a host (Google), path ties go to the
  template with fewer placeholders. Query and fragment are dropped before matching.
- Tier 1 also matches on the extracted vendor error code (`signal.error_code`) when the hash misses;
  tier 2 skips facts whose `error_code` contradicts an extracted one. A fact is indexed under the hash
  of `normalize(error_string)` and of `normalize(normalized)` (the 01 example's `normalized` drops the
  trailing period that the 03 rules keep).
- Pre-flight URL: facts of the template ∪ service `rate_limit`/`availability` facts. Bare host: all
  service facts. Locator: facts whose `target.sdk` is that package, filtered by `versions` when the
  version and constraint are simple comparisons (unparseable → kept).
- `observed`: `status_distribution_30d: {}`, `p50_latency_ms: null`, `last_probe: null` until W2 results
  exist; `rate_limit_headers` = the service's `signal_fields` that name a rate-limit header.
- Reporter net: IPv4 /16; IPv6 /32 (spec says /16, which for IPv6 is a few RIR blocks). Client IP =
  socket peer; `X-Forwarded-For` only when the peer is in `AGENTFACTS_TRUSTED_PROXIES` (default
  `127.0.0.1,::1`), rightmost untrusted hop.
- Salt: one row per UTC day in sqlite; older rows deleted at first use of a new day.
- `registry.version`: `AGENTFACTS_REGISTRY_VERSION` if set, else newest date in facts' provenance /
  evidence, else `"none"`.

## Ingestion rules (spec 03 / 05, implemented literally — changes need Edouard)

Store only when the target resolved to `(service, method, template)`; never store bodies, headers,
query, raw IP. Before any write: secret-shaped → `<redacted>`. Drop (answer, don't store, count):
error string with a URL outside the service's hosts, prompt markers, > 1 000 observations per reporter
net per day. Counters (`counters` table, per UTC day, no identifiers): `unregistered_target`,
`dropped_foreign_url`, `dropped_prompt`, `dropped_daily_cap`, `stored`.
