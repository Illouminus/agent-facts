# agent-facts (рабочее имя папки, не бренд)

**Проверенный changelog реальности для ИИ-агентов.** Открытый датасет типизированных фактов о том, что
сторонние машинные интерфейсы (HTTP API, SDK-пакеты, CLI) реально делают сегодня, в отличие от того,
что пишут их доки. Каждый факт датирован, привязан к версии и несёт воспроизведение, которое
перепроверяется запуском кода, без участия моделей. Цель первого года — стать местом, куда агент
смотрит перед тем, как действовать через чужой интерфейс. Деньги не цель (решение Edouard 17.10.2026).

## Почему это нужно
Главная операционная боль агентов по трём независимым панелям (Gemini, Claude, мой список) одна:
интерфейс изменился, доки врут, никто не сказал. Агенты платят токенами за перепроверку и
переоткрывают одни и те же ловушки в каждой сессии. context7 решает «дай правильные доки»; никто не
решает «доки неправы о том, что эта штука делает прямо сейчас, вот проверенная разница».

Примеры фактов: «stripe-python 21.1 убрал поле X из ответа 404», «Apollo отдаёт 200 с пустым массивом
вместо 429 при исчерпании кредитов», «Etherscan лимитирует через `status:0` в теле при HTTP 200»,
«Slack chat.postMessage отдаёт общий 400 при `blocks` длиннее 50».

## Что это НЕ
- Не аптайм-чекер: здоровье API — один тип факта из многих, побочный продукт (IsDown, StatusGator,
  Checkly уже есть).
- Не «единый источник правды обо всём»: только то, что проверяется запуском. Факты о мире, цены,
  мнения, stateful и платные эндпоинты, поведение за чужой авторизацией — вне области.
- Не второй context7: у него открытый клиент и закрытые данные; у нас открытые данные (CC-BY 4.0)
  и тонкий клиент.
- Не ещё один «Stack Overflow для агентов» (MoltyOverflow, AgentKB, cache.overflow, AgentsKB): там
  Markdown и голоса агентов без проверки, у нас типизированные факты и проверка запуском. Их цифры на
  18.10.2026 (69 решений; 4 агента, 0 принятых ответов) показывают, что сами по себе агенты не контрибьютят.
- Не приватный монитор дрейфа (FlareCanary, Routebase, DriftSignal): они следят за твоими N эндпоинтами
  за подписку; мы — открытый кросс-компанийный commons о чужих интерфейсах.

## Как работает
1. **Единица данных** — факт: сервис, эндпоинт или пакет@версия, вид (поведение статуса, требуемый
   заголовок, вариант схемы, поведение лимита, breaking change), измерения (тариф, регион, точка
   обзора, версия SDK), first-seen, источник, воспроизведение (HTTP-запрос с утверждением или скрипт
   песочницы), статус: `verified:server:prod` / `verified:server:sandbox` / `verified:client` / `reported` / `official`;
   измерения `env`, `plan`, `region`, `account_state` — проба в другой среде факт не опровергает.
2. **Вход для агента — один инструмент `check(target, error?)`** (MCP + HTTP): после отказа, до вызова
   (pre-flight «известные ловушки эндпоинта») и при тихой аномалии («200 и пустой массив»). Он отвечает (проверенные
   факты и «что видят другие») и одновременно записывает наблюдение из самого вопроса. Отдельного шага
   «внеси вклад» нет: запрос = вклад. PR — формат для людей и производителей.
3. **Верификация — запуск кода, никогда не модель.** Пробы с трёх точек (illouminus, прод-VPS,
   резидентный выход) для публичных GET; песочница для фактов о пакетах и CLI. Наблюдения — подсказка,
   проба — истина: состояние меняет только проба. Что не проверяется исполнением — честно `reported`.
4. **Хранилище — публичный git-репозиторий**: факт = YAML-файл, бот коммитит после кворума или пробы,
   CI = GitHub Actions + свои пробы, история и споры видны. Страница на каждый факт и строку ошибки,
   llms.txt, статический JSON на CDN (ответ < 150 мс).
5. **Лестница вклада** по убыванию автоматизма: наши пробы → запрос как вклад → плагины pytest/jest и
   CLI `capture` (упавший тест = готовое репро) → пассивный OpenTelemetry-экспортер → ручные PR.

## Инварианты и защиты
- Ни одного вызова LLM в цикле верификации; у раннера нет ключей к API моделей.
- Фиксы только типизированные из перечисления; ни свободного текста, ни shell; URL только с доменов
  владельца.
- Default-deny на входе: только пути по зарегистрированным шаблонам, без query-строк, тел и заголовков;
  строки ошибок — данные с лимитом символов и длины, никогда в описания инструментов.
- Публикация агрегатов при k независимых источников; лимиты на ключ, цель, /16, сборку SDK; kill switch
  версии; бюджет вежливости ≤ 1 запрос / 5 мин на эндпоинт.
- Аккаунты на чужих сервисах — наши, заведены Edouard вручную, предпочтительно sandbox/test-режимы;
  ключи инжектятся ТОЛЬКО в наш раннер проб и НИКОГДА в песочницу с репродукциями контрибьюторов.
  Исключены сервисы, чьи условия запрещают автоматический доступ или публикацию замеров (LinkedIn, X).
  Честный User-Agent, opt-out, адрес для takedown.
- Подпись производителя бесплатна всегда.

## Автономия (решение 20.10.2026)
Проект развивается сам; ядро — рутины illouminus с журналом и карточками в state. Агент решает сам: факты,
пробы, страницы, версии плагинов, сервисы без ключей, kill switch (Edouard получает сообщение). По тапу
Edouard: деньги, новые аккаунты и ключи, изменение правил приёма. Публикации наружу — пачкой в недельном
дайджесте, один тап на пачку; шаблоны и список вендоров утверждены заранее. Бюджет Edouard: два-три часа на
старте (список семени, аккаунты, репо, домен), затем ~10–15 мин/нед.

## Стадии
A «Обсерватория»: плотное семя 8–10 сервисов × ≥10 фактов (наши аккаунты, sandbox-режимы), `check(target, error?)`,
MCP, страницы, плагины pytest/jest, пробы как фон;
~1 агент-час/нед, Edouard ~10–15 мин/нед. B «Подсказки»: пассивный OTel-экспортер, наблюдения запускают пробы. C «Утверждения»:
типизированные утверждения со ставкой, официальные записи производителей. Никогда: рецепты с shell,
тестовые аккаунты, stateful эндпоинты, факты о мире.

## Как о нас узнают (без маркетинга)
Четыре двери: поиск по строке ошибки в момент отказа (страница на факт, те же файлы на github.com);
реестры MCP; место рождения факта (issue у вендора, ответ на Stack Overflow — пачкой в недельном дайджесте, один тап Edouard на пачку);
код оператора (плагины тест-раннеров, middleware во фреймворках). Не «3 000 статей»: это scaled content
abuse. План на 6 недель — docs/plan-2026-10-17.md §18.

## Замеры и пороги
К неделе 8 стадии A: ≥50–100 уникальных вызовов `check()`/нед суммарно и ≥3–5 подтверждённых новых находок от
внешних агентов — иначе стоп; порог «≥1 000 наблюдений/нед на оператора» — только после OTel-экспортера (B);
деньги не мерим. Опережающий индикатор — доля `is_it_me` и хотя бы одна
поимка дрейфа раньше официальной статус-страницы.

## Что уже известно (доказательства в docs/)
- Агенты с кошельком мелким продавцам не платят: медиана 1 чужой плательщик и $0.01 за 30 дней на
  2 039 продавцах x402 в Base (docs/research/x402-demand-2026-10.md). 402 — не канал.
- Никто не агрегирует клиентские наблюдения по сторонним API кросс-компанийно и не ловит дрейф схем в
  живом трафике (docs/panels/gemini-incumbents-api-health.md, проверено 17.10).
- Пять агентов: пользоваться будут после отказа, доверять — репро и дате, PR сами не откроют.
  Пять покупателей: за открытые данные не платит никто, платят за вебхуки по своему манифесту,
  self-hosted верификатор, телеметрию производителей, латентность (docs/panels/gemini-panel3-*.md).
- Главный риск всех панелей: реальность не детерминирована (тариф, регион, антибот) — ответ в
  измерениях схемы и честном статусе `reported`.
